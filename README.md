# Telegram Monitor - Мониторинг чатов отдела продаж

Скрипт для автоматического мониторинга Telegram аккаунта отдела продаж с целью контроля своевременности ответов клиентам.

## Описание

Скрипт анализирует все чаты общего Telegram аккаунта компании. В зависимости от переменной `REPORT_TYPES` (список через запятую) он может одновременно формировать несколько отчётов:

- **`unread`** — выявляет непрочитанные сообщения от клиентов
- **`unanswered`** — выявляет неотвеченные сообщения (последнее сообщение в чате от клиента, без нашей реакции)
- **`leaderboard`** — строит топ переписок по среднему времени ответа менеджера

Режимы можно комбинировать, например `REPORT_TYPES=unread,unanswered` или `REPORT_TYPES=unread,unanswered,leaderboard`. Каждый включённый режим отправляется указанному пользователю отдельным сообщением (по умолчанию `@victorryakh`).


## Бизнес-логика

### Описание контекста работы с Telegram аккаунтом

В AIESEC в Москве используется общий аккаунт Telegram для департамента OGX (Outcoming Global Exchanges) для общения с потенциальными стажёрами. По сути - отдел продаж

В связи с тем, что организация является некоммерческой и существует исключительно на личной инициативе молодых людей, трекинг регулярного взаимодействия со стажёрами (клиентами) является важной частью аналитики

Таким образом, данный репозиторий нацелен на то, чтобы сделать работу OGX депаратамента измеримой и прозрачной

Сами переписки ведутся долго: от недели до нескольких месяцев

### leaderboard mode why behind

Так как каждый менеджер (мембер OGX департамента) работает самостоятельно с каждым клиентом (стажёром), то условная скорость коммуникации тоже разная

Для предоставления сервиса клиентам высокого уровня, требуеются своевременные сообщения в переписке от менеджера к клиенту

leaderboard mode должен отражать лучшие по "качеству" переписки по данному критерию для поощрения тех менеджеров, которые ответственно подходят к своей работе

### Параметры лидерборда

Анализ ведётся за последние `LEADERBOARD_RESPONSE_WINDOW_DAYS` дней (по умолчанию 7), а не за фиксированное число сообщений — это отражает именно свежее поведение менеджера. Чтобы топ не «шумел» из-за единичных пар, в него попадают только чаты с количеством пар «клиент→менеджер» не ниже `LEADERBOARD_MIN_PAIRS` (по умолчанию 3). Количество пар по каждому чату выводится в строке топа для прозрачности.

Отчёт `liveliness` дополняет скоростной лидерборд: ЛПР смотрит на пересечение двух топов для выявления переписок с одновременно быстрым и активным менеджером. Метрика живости — общее количество сообщений в окне (входящие + исходящие), порог `LEADERBOARD_MIN_PAIRS` применяется к обоим отчётам явно. Чат, в котором менеджер вообще не ответил ни разу, тоже попадает в выборку (с `pairs=0`) и исключается тем же `LEADERBOARD_MIN_PAIRS`; при `LEADERBOARD_MIN_PAIRS=0` такие чаты видны в обоих отчётах — это сигнал «клиент активен, но менеджер молчит».

### Семантика подсчёта среднего времени ответа

Пары «сообщение клиента → ответ менеджера» формируются по следующим правилам:

- Если клиент подряд отправил N сообщений, а затем менеджер ответил один раз — это **одна пара**, и время ответа измеряется от **последнего** клиентского сообщения в этом burst'е до ответа менеджера.
- Если менеджер отправил подряд M сообщений без вмешательства клиента, в зачёт идёт **только первое** сообщение менеджера после клиента. Остальные отбрасываются, чтобы не искажать среднее.
- Сообщения менеджера, у которых нет предшествующего сообщения клиента в пределах анализируемого окна, игнорируются.
- Итоговое значение по чату — среднее арифметическое по всем собранным парам.

## Особенности

✅ **Реакции как ответ** - проставленная реакция на сообщение клиента считается ответом
✅ **Исключение чатов** - возможность исключить определенные чаты из мониторинга
✅ **Кеширование сессии** - не требуется повторная авторизация при каждом запуске
✅ **Фильтрация каналов** - каналы не учитываются, только личные чаты и группы
✅ **Docker Compose** - готовый к запуску контейнер с bind mount сессии
✅ **Топ по скорости ответа** - рейтинг переписок с наименьшим средним временем ответа

## Требования

- Docker и Docker Compose
- Telegram API credentials (API ID и API Hash)
- Доступ к Telegram аккаунту (номер телефона)

## Установка

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd telegram-police
```

### 2. Получение Telegram API credentials

1. Перейдите на <https://my.telegram.org/auth>
2. Войдите с номером телефона вашего аккаунта
3. Перейдите в раздел "API development tools"
4. Создайте новое приложение (если еще не создано)
5. Скопируйте **API ID** и **API Hash**

### 3. Настройка `.env`

Создайте файл `.env` в корне проекта (или скопируйте из примера):

```bash
cp env.example .env
```

Заполните обязательные переменные:

```env
API_ID=12345678
API_HASH=your_api_hash_here
PHONE=+79991234567
```

Полный список переменных с описанием — в разделе [Конфигурация](#конфигурация).

### 4. Первичная авторизация

При первом запуске Telegram запросит код подтверждения. Это нужно сделать интерактивно:

```bash
docker compose run --rm telegram-police
```

Вы получите:

1. Код в Telegram (от Telegram)
2. Запрос на ввод кода в терминале
3. Возможно, запрос пароля двухфакторной аутентификации (если включена)

После успешной авторизации в корне проекта создастся файл `session.session`. Он монтируется в контейнер через bind mount и сохраняется между перезапусками.

## Использование

### Запуск через Docker Compose

```bash
# Собрать образ и запустить
docker compose up --build

# Запустить в фоне
docker compose up -d

# Однократный запуск (без restart: unless-stopped)
docker compose run --rm telegram-police
```

### Просмотр логов контейнера

```bash
docker compose logs -f
```

### Остановка

```bash
docker compose down
```

```bash
crontab -e

# Запуск каждый час
0 * * * * cd /path/to/telegram-police && docker compose run --rm telegram-police
```

## Конфигурация

Все параметры задаются через файл `.env`. Переменные с пометкой **обязательно** не имеют значения по умолчанию.

| Переменная | Обязательно | По умолчанию | Описание |
| --- | --- | --- | --- |
| `API_ID` | ✅ | — | Telegram API ID |
| `API_HASH` | ✅ | — | Telegram API Hash |
| `PHONE` | ✅ | — | Номер телефона аккаунта |
| `REPORT_TO` | | `@victorryakh` | Username получателя сводки |
| `REPORT_TO_THREAD` | | — | ID треда (топика) в группе, куда слать сводку (если задан — используется `comment`) |
| `EXCLUDED_CHATS` | | `["@PremiumBot","@SpamBot"]` | JSON-список исключённых чатов (см. ниже) |
| `REPORT_TYPES` | | `unread,unanswered` | Список типов отчёта через запятую. Допустимые значения: `unread`, `unanswered`, `leaderboard`, `liveliness` |
| `LEADERBOARD_RESPONSE_LIST_COUNT` | | `10` | Количество чатов в топе (для `leaderboard`) |
| `LEADERBOARD_RESPONSE_WINDOW_DAYS` | | `7` | Окно анализа в днях (для `leaderboard`) |
| `LEADERBOARD_MIN_PAIRS` | | `3` | Минимальное число пар «клиент→менеджер» для попадания чата в топ (для `leaderboard`) |
| `LEADERBOARD_RESPONSE_MESSAGES_COUNT` | | `100` | Legacy: не используется, выборка сообщений теперь ограничена только окном `LEADERBOARD_RESPONSE_WINDOW_DAYS`. Оставлено для обратной совместимости. |

### Примеры `EXCLUDED_CHATS`

В `EXCLUDED_CHATS` можно указать:

- **`@username`** — каналы/группы/пользователи по username
- **Название** — чаты/группы по `title` (для пользователей — по `first_name + last_name`)
- **Числовой `chat_id`** — Telegram ID чата (например `-1001234567890` для супергрупп)

```env
# По username
EXCLUDED_CHATS=["@spambot","@notifications"]

# По названию группы
EXCLUDED_CHATS=["Внутренний чат","Spam Group"]

# По chat_id (числовой Telegram ID)
EXCLUDED_CHATS=["-1001234567890"]

# Смешанный список
EXCLUDED_CHATS=["@bot","Внутренний чат","-1001234567890"]
```

## Логика работы

### Время с момента отправки

Время ответа считается как разница между временем ответа менеджера и временем сообщения клиента. Цветовые индикаторы используются в отчётах `unread` и `unanswered`:

- 🔵 менее 2 часов
- 🟡 2–4 часа
- 🔴 более 4 часов

В отчёте `leaderboard` цветовые индикаторы не выводятся — только среднее время ответа.

### Реакции как ответ

Если на сообщение клиента была поставлена реакция от вашего аккаунта, это считается ответом, и сообщение НЕ попадает в сводку неотвеченных.

### Топ по скорости ответа (`leaderboard`)

Для каждой переписки берутся последние `LEADERBOARD_RESPONSE_MESSAGES_COUNT` сообщений. По каждой паре «сообщение клиента → первый ответ менеджера» считается время ответа (см. раздел [Семантика подсчёта](#семантика-подсчёта-среднего-времени-ответа)). Итоговый показатель — среднее по всем парам. В отчёт попадают `LEADERBOARD_RESPONSE_LIST_COUNT` переписок с наименьшим средним временем ответа. Чат, в котором не набралось ни одной пары, в топ не попадает.

## Форматы сводки

`unread` и `unanswered` — это **два отдельных сообщения**, каждое отправляется независимо. Если в `REPORT_TYPES` указаны оба — пользователь получит два сообщения подряд (плюс `leaderboard`, если он тоже включён).

### `unread` — если проблем нет

```text
✅ Непрочитанных сообщений нет — 07.05.2026 12:00
```

### `unread` — если есть проблемы

```text
📬 НЕПРОЧИТАННЫЕ СООБЩЕНИЯ (2) — 07.05.2026 12:00

🔵 @client1 (Иван Иванов) - 3 непрочитанных, первое от 07.05.2026 09:30
🟡 @client2 (Петр Петров) - 1 непрочитанных, первое от 07.05.2026 10:15
```

### `unanswered` — если проблем нет

```text
✅ Неотвеченных сообщений нет — 07.05.2026 12:00
```

### `unanswered` — если есть проблемы

```text
💬 НЕОТВЕЧЕННЫЕ СООБЩЕНИЯ (1) — 07.05.2026 12:00

🔴 @client3 (Мария Сидорова) - последнее сообщение от 07.05.2026 08:45

Чтобы сообщения не считались неотвеченными — ставь реакцию в конце сообщения собеседника
```

Цветовые индикаторы: 🔵 < 2ч · 🟡 2–4ч · 🔴 > 4ч

### `leaderboard`

```text
🏆 ТОП-10 ПЕРЕПИСОК ПО СКОРОСТИ ОТВЕТА МЕНЕДЖЕРА
(за последние 100 сообщений, 07.05.2026 12:00)

🥇 @client1 (Иван Иванов) — ср. ответ: 5м
🥈 @client2 (Петр Петров) — ср. ответ: 12м
🥉 @client3 (Мария Сидорова) — ср. ответ: 28м
4. @client4 (Анна Кузнецова) — ср. ответ: 1ч 3м
...
```

Если ни в одном чате не набралось ни одной пары «вопрос→ответ», вместо топа отправляется строка `Недостаточно данных для формирования топа.`

### `liveliness`

```text
🔥 ТОП-10 ПЕРЕПИСОК ПО ЖИВОСТИ ДИАЛОГА
(окно: 7 дн., мин. пар: 3, 07.05.2026 12:00)

🥇 @client1 (Иван Иванов) — 47 сообщ.
🥈 @client2 (Петр Петров) — 31 сообщ.
🥉 @client3 (Мария Сидорова) — 24 сообщ.
4. @client4 (Анна Кузнецова) — 18 сообщ.
...
```

Ранжирует чаты по общему количеству сообщений (входящие + исходящие) в окне `LEADERBOARD_RESPONSE_WINDOW_DAYS`. Применяется тот же порог `LEADERBOARD_MIN_PAIRS`, что и для скоростного лидерборда.

## Устранение неполадок

### Повторная авторизация

```bash
rm session.session
docker compose run --rm telegram-police
```

### Скрипт не находит непрочитанные сообщения

Убедитесь, что:

1. Сообщения действительно непрочитаны в Telegram
2. Чат не находится в `EXCLUDED_CHATS`
3. Это личный чат или группа (не канал)

### Скрипт не отправляет сводку

Проверьте:

1. Правильность `REPORT_TO` в `.env` (должен начинаться с `@`)
2. Наличие диалога с этим пользователем в Telegram
3. Логи: `docker compose logs`
